---
title: "Run a live meeting copilot"
description: "Surface people, action items, and decisions as a call happens — approve them into the workspace."
---

A **meeting copilot** rides the live transcript: a dispatch stays non-idle on
the stream and emits **proactive cards** — a new person, an action item, a decision — as they come up.
Approving a card commits it to your [workspace](/concepts#workspace). Same agent and governance as
everything else; only the trigger (the transcript stream) differs.

The flow usually starts before the call: [plan the meeting](/how-to/plan-a-meeting) (or let
[calendar sync](/how-to/calendar-sync) plan it), bind its prep workspace, and the bot auto-joins at
start — members of the bound workspace get the same live feed the copilot rides.

## 1. Start the copilot

The durable meeting **row id** is the processing and stream carrier: `meeting_id == session_uid`.
The reusable provider link id (`native_meeting_id`) is metadata only and is never a Redis carrier key.

```bash
curl -X POST "$API_BASE/bots" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"native_meeting_id":"abc-defg-hij","platform":"google_meet","bot_name":"Zaki Minutes"}'
# → 201, an owner-scoped meeting record; save its numeric `id` (41 below)
```

## 2. Turn processing on

Processing is opt-in. Toggle it on to start consuming the transcript:

```bash
curl -X POST "$API_BASE/agent/meeting/process" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"meeting_id":"41","native_id":"abc-defg-hij","platform":"google_meet","on":true}'
# → { ..., "processing": true, "resumed_from": "<cursor-id>" }
```

The retired native-only `POST /agent/meeting/start` endpoint returns `410`; it cannot establish
owner-scoped consent or bind work to the meeting's retention fence.

## 3. Stream the merged feed

Subscribe to the SSE stream that merges transcript and copilot output:

```bash
curl -N -H "X-API-Key: $API_KEY" \
  "$API_BASE/agent/meeting/stream?meeting_id=41&session_uid=41"
```

Event types on the stream: `transcript`, `card` (a proposal), `message-delta`, `tool-call`, `ping`,
`meeting-end`. Every event carries an SSE `id:` — on reconnect, echo it as `Last-Event-ID` to **resume
gaplessly**.

Approving a `card` commits it to the workspace (a person, an action item, a decision).

## Pause and resume mid-call

Toggle processing off to stop consuming without ending the meeting; the per-meeting **cursor freezes**.
Turn it back on and it resumes from exactly where it stopped:

```bash
# pause — revokes the worker generation, confirms runtime stop, freezes the cursor
curl -X POST "$API_BASE/agent/meeting/process" \
  -H "X-API-Key: $API_KEY" -H "Content-Type: application/json" \
  -d '{"meeting_id":"41","native_id":"abc-defg-hij","on":false}'
# → { ..., "processing": false }
```

`on:true` later resumes from the saved cursor (`"resumed_from":"<id>"`) — no re-processing, no gap.

## Health

```bash
curl -H "X-API-Key: $API_KEY" "$API_BASE/agent/meeting/relay-health"
```

A stale bot key surfaces as `native_resolve:{ok:false,kind:"unauthorized"}` rather than silent dead air.
